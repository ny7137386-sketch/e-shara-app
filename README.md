# e shara app

e shara is a small full-stack marketplace for handmade products with nearby clinic discovery and appointment booking. The existing single-page UI is served by an Express API and remains usable as a static fallback when the database is unavailable.

## Local setup

Requirements: Node.js 18+, npm, and PostgreSQL 14+.

```powershell
cd "C:\Users\ny713\OneDrive\Apps\Desktop\e shara app"
Copy-Item .env.example .env
# Edit DATABASE_URL and set a long, random JWT_SECRET in .env
createdb e_shara
psql "$env:DATABASE_URL" -f db/schema.sql
npm install
npm run check
npm start
```

Open http://localhost:3000. The API health check is available at `/api/health`.

Register customer or seller accounts from the login dialog/API. Admin accounts are intentionally not self-registerable; create one with a bcrypt hash:

```powershell
node -e "console.log(require('bcryptjs').hashSync('change-this-password', 12))"
```

Insert the resulting hash into `users` with `role = 'admin'`. Never commit `.env` or real passwords.

## API overview

- `POST /api/auth/register`, `POST /api/auth/login`
- `GET /api/products`; seller/admin `POST`, `PATCH`, and `DELETE /api/products/:id`
- Customer `GET /api/cart`, `POST /api/cart/items`, `DELETE /api/cart/items/:productId`, `POST /api/orders`
- Customer `GET /api/orders`; seller/admin order access is available through `GET /api/orders`
- Admin delivery partner CRUD and `POST /api/admin/orders/:id/assign`
- `GET /api/cities`, `GET /api/clinics?cityId=...`, customer `POST /api/appointments`
- Admin city/clinic creation at `/api/admin/cities` and `/api/admin/clinics`

Protected endpoints use `Authorization: Bearer <token>`. SQL uses PostgreSQL parameters throughout. Request validation, role checks, explicit JSON errors, Helmet, and configurable CORS are included.

## Deployment

Deploy to any Node host that supports a start command. Set `DATABASE_URL`, `JWT_SECRET`, `CLIENT_ORIGIN`, `PORT`, and `PGSSL=true` when required by the managed PostgreSQL provider. Run `npm ci` and `npm start`; execute `db/schema.sql` once against the production database. Use TLS at the host/proxy and a strong secret generated by the platform's secret manager.
